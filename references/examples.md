# Mapping patterns

Illustrative only: verify paths in the actual project before using them.

## Small project

Add a short Project Map section to an existing agent instruction file. Link its source entry point, tests and release guide. Do not add three new documents merely to satisfy a template.

## Larger repository

Create only useful area maps, usually 15–35 lines each. Each entry pairs a relative link with a specific purpose. Resolve relative paths from the map’s own directory.

## Monorepo

Use a root map linking package-level agent instructions and shared operations guidance. Preserve each package’s ownership and mandatory checks. Avoid a giant inventory of every source file.

## Existing work

Inspect the working-tree diff first. Preserve unrelated local changes. Reuse existing indexes, flag contradictory authorities, and validate map links without running project scripts. Repeat adoption should update the same maps, not create more maps.
